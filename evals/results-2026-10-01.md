Each prompt in [evals.md](evals.md) was run once per setup, in a fresh agent context, on the same model. The agents did not know they were being evaluated. Outputs were scored against the "Expect" and "Must not" items by hand, not blind.

## Findings

- The original skill's "apply every rule" and "fix nearby violations" instructions caused scope creep (evals 2, 8), ceremony in throwaway code (eval 3), and over-fragmentation (eval 1). Its "Replace Exception with Test" rule produced the look-before-you-leap bug in eval 6.
- The base model already writes clean Python: `Decimal` for money, named constants, EAFP, and specific exceptions appeared without any skill.
- The skill's clearest value is in reviews (consistent format, impact ordering, concise) and in keeping changes proportional. v2 produced the smallest correct output in most evals and followed the "suggest, don't do" rule for out-of-scope improvements (eval 8).
- ruff findings were similar across setups and did not distinguish them.

## Limitations

- One run per prompt per setup; results are directional, not statistically meaningful.
- Scoring was done by hand with knowledge of which setup produced each output.
- Single model. Re-run when the model or `SKILL.md` changes, ideally 3–5 runs per prompt with blind scoring.
